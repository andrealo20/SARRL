# v2.8: Panda filter on the selected delay

The v2.6 joint filter aborted 107 of 120 fast moves before any QP, because it
checked queued commands under every constant delay from 0 to 40 ms at once,
and its 20 unsafe episodes were all at 40 ms. The v2.7 diagnosis left two
possible causes. This release tests one of them with a single change: the
filter's constraints are built only over the delay ages whose accumulated
bank score equals the minimum, the ages the bank cannot yet tell apart. It
promotes nothing. The cumulative constant-delay bank and the planar
adaptive/covariance-margin controller remain the references.

The [methods](panda-selected-filter.md) were frozen at `1812d9d`, after three
rounds of independent adversarial review, and sealed at `2cceedb`. The run
first reproduced all 480 v2.6 records through the new entry point, then opened
twenty fresh paired seeds on three arms: cumulative alignment, the v2.6 filter
and the narrowed filter.

| Fast moves, 120 tasks | Successes | Unsafe | Aborts |
|---|---:|---:|---:|
| cumulative | 28 | 92 | 0 |
| v2.6 filter, ages 0..4 | 24 | 16 | 96 |
| selected-delay filter | 36 | 23 | 84 |

All three predictions fixed before the run hold. At 20 ms aborts fall from 16
to 14 in both cells; at 40 ms they stay at 16 and violations remain; one
zero-delay episode becomes unsafe. No task the v2.6 filter completed is lost,
and twelve are gained. Seven tasks the v2.6 filter kept safe exceed the
velocity limit under the narrowed filter, each after an abort that comes later
than the v2.6 one on the same task, so the candidate does not advance. The
zero-delay case, with no command in flight, aborts because the measured state
has already left the barrier domain. The [results](panda-selected-filter-results.md)
list every cell and every new violation.

## Components and scope

| Component | Status |
|---|---|
| `ages` argument of the joint filter | Default keeps the v2.6 construction; reproduced on 480 records |
| Selected-age mode of the filtered controller | Experimental; failed `no_new_violations` and the v2.6 advancement criteria |
| Runner and causal auditor | Retained with the results |

The scope is the v2.6 grid: constant on-grid delays of 0, 20 and 40 ms with a
zero-initialised command queue, ordinary and fast moves, clean and noisy
measurements, sampled payload and friction. Changing latency, collision
avoidance, hardware and sim-to-real are outside it. The estimated model is not
a physical certificate.

## Audit

The results record SHA256 fingerprints of the sources at `2cceedb`, and later
commits change them, including the version number of this release. Audit from
a detached worktree at that commit with Python 3.12.3, NumPy 2.5.2, SciPy
1.18.1 and MuJoCo 3.13.0:

```bash
python -m pip install -e '.[mujoco]' 'numpy==2.5.2' 'mujoco==3.13.0' 'scipy==1.18.1'
git worktree add --detach ../SARRL-selected-audit 2cceedb6d78ed00854add86d42de418c8c0d5865
cd ../SARRL-selected-audit
python -m tools.audit_panda_selected_filter --input <checkout>/results/panda_selected_filter_pilot
```

The auditor compares regenerated commands with delivered torques exactly and
passed on the production host; a host that differs in the last floating-point
bit can fail it. Earlier reports keep the audit commands in their own
[release guides](v2.7.md).

## Following work

Besides the command queue, the zero-delay violation implicates the estimated
model and the velocity reserve, which v2.8 left untouched by design.
Any successor needs its own frozen protocol and a seed block above `9806299`.
See the [roadmap](roadmap.md).
