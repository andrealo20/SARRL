# v2.7: Panda backup diagnostics and validated prefixes

This release asks why the two v2.6 candidates failed and whether a delayed
Panda backup can be verified offline. It promotes nothing. The cumulative
constant-delay Panda bank and the planar adaptive/covariance-margin controller
remain the references.

The diagnoses use saved records. Planar residual losses are mostly timeouts,
284 of 298. Every Panda filter abort comes from torques already in the command
queue, which a projection cannot withdraw. A backup supervisor that respects
the queue removed four unsafe episodes on already-observed tasks but added two
position violations, because its frozen model drifted from the plant.

The backup study then moved to an enclosure of the normalized seven-joint
model in 128-bit validated arithmetic, on one fixture: HOME, payload mass in
[0.5, 2.5] split into sixteen cells, viscous friction in [0.5, 3], five
constant lags and six held 10 ms periods, 80 branches and 480 periods.

zero runtime defects, constant lags and one fixture that is now exposed. None

terminal set. Existing figures, replay videos and the supplied SVG banner are
preserved.

## Audit the retained reports

Each report records SHA256 fingerprints of the package sources, and later
commits change them, including the version number of this release. Audit every
report from a detached worktree at its own freeze, with Python 3.12.3, NumPy
2.5.2, SciPy 1.18.1, MuJoCo 3.13.0 and python-flint 0.9.0:

```bash
python -m pip install -e '.[mujoco,numerics]' 'numpy==2.5.2' 'mujoco==3.13.0' 'scipy==1.18.1'
git worktree add --detach ../SARRL-substep-audit 290dc050d8261082c8d6efeacea4ae4b526b5898
cd ../SARRL-substep-audit
python -m tools.assess_panda_substep_prefix --audit \
  --output results/panda_substep_prefix/assessment.json.gz
```
