# v2.3: seven-joint Panda control and identification

Version 2.3 adds a torque-controlled, fixed-base Panda simulation, online
payload/friction identification and command-history alignment to the
existing planar stack. The robot model, collision meshes, attribution and
license are included in the Python package. Existing planar APIs, learned
policies and HOCBF results retain their previous scope.

## Run a short example

From a checkout of this release:

```bash
python -m pip install -e '.[mujoco]'
python examples/panda_reach.py
```

The example runs one three-second nominal joint trajectory and prints
physical diagnostics as JSON. It uses an already-open engineering-test
seed and writes no files. Success should be true, with 300 control steps.
Numerical values can differ between MuJoCo versions. This is an installation
and API example, not a new benchmark result. Panda checks have run on
MuJoCo 3.13.0 and 3.15.0; exact retained-data reproduction uses the versions
in each manifest.

## Reference and experimental components

| Component | Release scope |
|---|---|
| `PandaReachEnv`, `PandaComputedTorqueController` | Nominal joint-trajectory simulation and substep constraint measurements |
| `PandaAdaptiveController` | Bounded online payload and added viscous-friction identification |
| `PandaDelayController(predict=False)` | Cumulative-score alignment reference for constant on-grid command delay |
| `PandaDelayController(predict=True)` | Experimental queued-command prediction; some tested conditions regress |
| `PandaPacketInterface` | Experimental changing packet latency with hold and stale-packet rejection |
| `PandaScoreMemoryController` | Experimental exponential/window scoring; partial age recovery with tracking regressions |

The Panda controls joint position trajectories. The Cartesian endpoint
comes from forward kinematics of the joint goal. Cartesian inverse
kinematics, residual-policy training, seven-joint HOCBF filtering and
hardware execution are not included in this release.

## Retained evidence

Seven descriptive pilots cover nominal tracking, payload/friction,
sensor noise, constant delays, wider postures, warm startup and changing
latency. Full protocols, every retained episode, selected traces, figures
and completion hashes remain available:

- [Nominal model and tracking](panda.md).
- [Payload/friction identification](panda-adaptation.md).
- [Sensor noise and delay](panda-robustness.md).
- [Delay identification and prediction](panda-delay.md).
- [Posture and constant-delay grid](panda-posture-delay.md).
- [Warm startup and changing latency](panda-variable-delay.md).
- [Score-memory comparison](panda-score-memory.md).

The constant-delay grid retained 400/400 successful bank-alignment
episodes across two posture ranges, five delays and two noise levels.
Changing latency exposed a limitation: the last pilot's cumulative bank
identified the final age in 1/160 changing episodes, exponential in 74/160
and the window in 72/160. All reached their targets, but both finite-memory
variants worsened final error and RMS after 1 s in every noisy changing
condition. Cumulative scores remain the reference.

The score-memory manifest's estimator description mentions parameter
forgetting in error. The frozen candidate RLS uses cumulative information
and covariance updates without a forgetting factor. Only hypothesis scores
forget. The original artifact is preserved; the current protocol text and
documentation correct that description. Controller arithmetic and retained
metrics are unchanged.

## Audit frozen results

Manifest hashes refer to the source state used for data, not to the newest
release's documentation or metadata. Use the recorded source commit and
Python/NumPy/MuJoCo versions. Frozen commits are preserved in release history.
For the last pilot, from a clone named `SARRL`:

```bash
git worktree add --detach ../SARRL-score-audit c4736d4
cd ../SARRL-score-audit
# Use the recorded Python 3.12 runtime.
python -m pip install 'numpy==2.5.2' 'mujoco==3.13.0'
python -m tools.audit_panda_score_memory \
  --input ../SARRL/results/panda_score_memory_pilot
```

The audit uses saved records and inverse-dynamics/estimator replay without
new physical episodes. It checks all 1,920 records and 96 traces, including
eighty causal estimator replays and independent score-weight reconstruction.
For the preceding variable-latency pilot, use source commit `8900bc6` and
`tools.audit_panda_variable_delay` with its retained result directory.
Completed campaign outputs are never replaced by these audits.

## Next work

Diagnose how candidate parameter fitting and trajectory excitation
distinguish delay hypotheses before another score-memory choice. Multiple
switches and off-grid latency need separate comparisons on fresh seeds.
Seven-joint safety filtering and residual learning follow the controller
and estimator work. No-contact observations in these bounded simulator
tasks do not establish general collision avoidance or hardware safety.
